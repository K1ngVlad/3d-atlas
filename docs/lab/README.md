Документ для Claude Code. Планы готовит отдельный «оркестратор», код пишет Claude Code по этапам. Перед любой задачей этапа прочитай: этот файл → `docs/lab/contracts.md` → файл своего этапа (для этапа 2 — ещё `docs/lab/quiz-ux.md`).

## Повторная реализация (17–25.11.2026)

Этапы 0–1 уже были реализованы и приняты один раз, но коммиты не были отправлены в удалённый репозиторий и остались на недоступном компьютере. Работа воспроизводится заново **в отдельной ветке** (например, `lab-backend`) от текущего состояния `main`; по возвращении к старому компьютеру его локальные коммиты игнорируются. Уроки первой итерации вшиты в задачи этапов — читай их внимательно, это не «пожелания», а грабли, на которые уже наступали.

**Жёсткое правило: в конце каждого этапа — коммиты по задачам и `git push` в удалённый репозиторий.** Этап без push не считается завершённым.

## Объём минимальной версии

**Входит:** API Gateway (YARP), Consul, Catalog, Quiz, Analytics, RabbitMQ, PostgreSQL (одна инстанция, три БД), MinIO для `.glb`, контейнер `web` (собранный Angular под nginx), `docker compose` одной командой, начальные данные из `projects/app/public`, экраны «Тесты» и «Аналитика», сценарий демонстрации.

**Не входит (решение автора):** пользователи и авторизация (пользователь анонимный, `clientId` в `localStorage`), Redis, k6, outbox, загрузка моделей, вопросы «Найдите на модели» и со вводом текста (техдолг — `quiz-ux.md`).

## Архитектура

```
Браузер ──▶ gateway :8080 (YARP)
              ├─ /api/catalog/**   ─▶ catalog   (C#, ASP.NET Core) ─▶ catalog_db
              ├─ /api/quiz/**      ─▶ quiz      (NestJS)           ─▶ quiz_db
              ├─ /api/analytics/** ─▶ analytics (FastAPI)          ─▶ analytics_db
              ├─ /models/**        ─▶ minio:9000/models/**  (статический адрес)
              └─ /**               ─▶ web (nginx + собранный Angular)

quiz ──REST (адрес из Consul)──▶ catalog
quiz ──RabbitMQ: quiz.events──▶ analytics
catalog, quiz, analytics ──регистрация, health──▶ consul ◀──адреса── gateway, quiz
catalog ──при каждом старте──▶ minio (синхронизация .glb из projects/app/public/models)
```

Ключевое: **один origin.** Клиент открывается через gateway, поэтому `model.url` в манифестах (`models/animal-cell/v1/…`) работает без изменений, а CORS не нужен. В dev-режиме `ng serve` проксирует `/api` и `/models` на gateway.

## Правила для Claude Code

1. Жёсткие правила из `CLAUDE.md` действуют. `projects/viewer-core` в этой работе **не меняется** вообще.
2. **Контракт сначала.** Изменение API, события или схемы БД — сначала правка `docs/lab/contracts.md`, потом код (как правило 6 для манифеста).
3. Документы — на русском; код, идентификаторы, коммиты — на английском. **Коммит на каждую законченную задачу этапа, `git push` в конце этапа.**
4. Каждый этап заканчивается разделом «Проверка» своего файла: выполнить на запущенном `docker compose`, записать в «Отчёт» результат **каждого** пункта (команда → что увидели), отметить пункты в `docs/roadmap.md` (Этап 9) и в чек-листе этапа. Без результатов проверок этап не принимается.
5. **Версии: проверять командами, а не по памяти** (`npm view <пакет> version`, `docker pull`, `dotnet package search`), брать актуальные стабильные и **закреплять теги образов** (никаких `latest`). Исключение MinIO — решение 42 в `contracts.md`.
6. Секреты только в `deploy/.env` (в `.gitignore`); в репозитории — `deploy/.env.example`.
7. Не добавлять то, что вынесено в «Потом», без отдельной задачи.
8. Если план расходится с реальностью (библиотека не работает, подход не подходит) — выбрать простейшую рабочую альтернативу, записать решение в `docs/decisions.md` и упомянуть в отчёте по этапу.
9. В конце этапа — короткий отчёт в разделе «Отчёт» файла этапа: что сделано, что отклонилось от плана, что осталось.
10. **Не переписывать существующие файлы целиком ради точечной правки** (особенно `decisions.md`, `roadmap.md`): только добавлять строки. Следить за переводами строк — в репозитории LF (`.gitattributes`, этап 0).
