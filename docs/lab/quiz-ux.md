# UX-спецификация: экран тестов

Дополняет `docs/02-ux-spec.md` (экран атласа). Раскладка, токены, шапка и поведение холста — как в атласе, если ниже не сказано иное. Источник истины для поведения — этот текст; макетов нет, ориентир по стилю — `design/02-desktop-selected.png` (правая панель).

Только десктоп. Мобильная версия тестов — вместе с мобильной версией атласа (этап 7 `roadmap.md`).

## Принятые решения

| # | Решение | Почему |
|---|---|---|
| Т1 | Экран тестов = просмотрщик модели слева + панель теста справа (вместо панели описания) | `02-ux-spec.md`: «похож на атлас, но в правой панели тест»; просмотрщик один на все экраны |
| Т2 | Типы вопросов сейчас: **один ответ** (радиокнопки) и **несколько ответов** (флажки). Ввод текста — в техдолге | Ручной ввод на русском плохо проверяется автоматически: падежи, сокращения («ЭПР» / «эндоплазматическая сеть»), опечатки, «ё». Ложные «неверно» на верный ответ подрывают доверие к тесту. Два типа с вариантами дают разнообразие без этого риска |
| Т3 | Вопрос «несколько ответов» засчитывается, только если выбраны **ровно** все верные варианты | Просто объяснить, просто считать; частичные баллы — потом |
| Т4 | Режим обучения: результат и правильный ответ показываются **сразу после каждого вопроса** | Платформа обучающая: студент видит ошибку, пока помнит вопрос, и читает описание органоида. Режим экзамена (итог только в конце) — техдолг |
| Т5 | Вопросы идут **строго по порядку**, без возврата к предыдущему | Правильный ответ уже показан — возврат и исправление обесценивают результат |
| Т6 | Вместо «Пропустить» — кнопка **«Не знаю»**: вопрос засчитывается неверным, правильный ответ и описание показываются | Нет состояния «пропущен, вернусь потом» (сложная навигация); студент всё равно узнаёт ответ |
| Т7 | Прохождение не теряется при перезагрузке и уходе со страницы: попытка хранится на сервере, клиент помнит её id и продолжает с первого неотвеченного вопроса | Это же демонстрация stateless-сервиса: экземпляр Quiz может упасть — попытка в БД |
| Т8 | Имя студента не спрашиваем | Пользователи анонимны (решение 37); аналитика агрегатная |
| Т9 | Во время вопроса сноски, подсветка при наведении, расслоение и выбор кликом выключены; вращение и масштаб работают | Сноски и выбор кликом выдают ответ; повертеть выделенную часть — полезно |
| Т10 | Вопросы могут быть по любой готовой модели, в том числе детальной (митохондрия, ЭПР, Гольджи): у вопроса свой `manifestId` | Механизм тот же, что у атласа: модель — это манифест; детальные модели — самое интересное для проверки знаний |
| Т11 | Пользователь узнаётся только по браузеру: `clientId` и `attemptId` в `localStorage`. Сервер хранит попытку, браузер хранит ключ к ней | Пользователи анонимны (решение 37). Честное ограничение: другой браузер, другое устройство, режим инкогнито или очистка данных сайта — новая попытка |

## Маршруты

| Маршрут | Что на экране |
|---|---|
| `/quiz` | список тестов в панели; на холсте — модель клетки (просто для фона, без выбора) |
| `/quiz/:quizId` | прохождение: продолжить незавершённую попытку этого теста или начать новую |

Пункт «Тесты» в шапке ведёт на `/quiz`.

## Список тестов (`/quiz`)

Панель:
- Заголовок «Тесты», подзаголовок «Проверьте, как вы знаете строение клетки».
- Карточка на каждый тест:
  - название, описание (до 2 строк), «10 вопросов»;
  - состояние (из `localStorage` этого браузера):
    - не начат — кнопка **«Начать»**;
    - есть незавершённая попытка — «Пройдено 3 из 10», кнопки **«Продолжить»** и текстовая «Начать заново»;
    - завершён — «Последний результат: 7 из 10», кнопка **«Пройти ещё раз»**.
- Состояния панели: загрузка (скелетон карточек), ошибка («Не удалось загрузить тесты» + «Повторить»), пусто («Тестов пока нет»).

Холст: модель из `manifestId` первого теста (клетка), обычный вид, без выбора кликом и без сносок; панель вида скрыта.

## Прохождение (`/quiz/:quizId`)

### Старт
1. Загрузить тест (`GET /quizzes/:id`).
2. Есть сохранённый `attemptId` для этого теста → `GET /attempts/:id`: если попытка не завершена — продолжить с первого вопроса без ответа; если завершена, не найдена или ошибка 404 — забыть её и начать новую.
3. Нет сохранённой попытки → `POST /attempts`, сохранить `attemptId`.
4. «Начать заново» из списка — забыть сохранённую попытку и создать новую (старая остаётся в БД незавершённой).

### Раскладка панели во время вопроса
Сверху вниз:
- Надзаголовок: «ТЕСТ · <название теста>»; справа — кнопка-крестик «Выйти» (на `/quiz`, без подтверждения: прогресс сохранён).
- «Вопрос 3 из 10» и полоса прогресса из сегментов по числу вопросов: отвеченный верно — акцент/зелёный, неверно — красный, текущий — обведён, будущие — серые.
- Текст вопроса (крупнее основного текста).
- Подсказка серым: «Выберите один ответ» / «Выберите все верные ответы».
- Варианты — строки на всю ширину (цель касания ≥ 44 px), клик по всей строке; радиокнопка или флажок слева.
- Подвал панели (прижат к низу): основная кнопка **«Ответить»** (неактивна, пока ничего не выбрано) и текстовая кнопка **«Не знаю»**.

Клавиатура: `1`–`9` выбирают вариант, `Enter` — «Ответить» / «Дальше».

### После ответа
- Варианты блокируются. Подсветка:
  - выбранный верный — зелёный фон, ✓;
  - выбранный неверный — красный фон, ✗;
  - невыбранный верный — зелёная рамка, ✓ и пометка «верный ответ».
- Над вариантами — плашка **«Верно»** (зелёная) или **«Неверно»** (красная).
- Ниже вариантов — карточка органоида (данные из Catalog, которые вернул Quiz): надзаголовок «ОРГАНОИД», название, описание, ссылка **«Открыть в атласе»** (в новой вкладке — чтобы не прерывать тест).
- Catalog недоступен (`entity: null`) — карточки нет, вместо неё серым «Описание сейчас недоступно». Ответ при этом проверен как обычно.
- Подвал: **«Дальше →»**, на последнем вопросе — **«Завершить тест»**.

### Холст во время вопроса
- Сноски, подсветка при наведении, расслоение — выключены; панель вида и крошки скрыты; кнопка «Сбросить вид» — оставить (в углу холста).
- Клик по модели ничего не выбирает и не открывает детальный уровень; вращение и масштаб работают.
- **Вопрос «Что выделено на модели?»** (у вопроса есть `partId`): загрузить `manifestId` вопроса (если отличается от текущего — с индикатором загрузки, как в атласе), выбрать часть с подлётом камеры и включённой изоляцией (остальное приглушено).
- **Обычный вопрос** (без `partId`): модель `manifestId` вопроса или теста, без выбора, камера — исходный вид.
- **Вопросы по детальным моделям** (`manifestId` вопроса — `mitochondrion`, `golgi`, `endoplasmic-reticulum`): модель загружается напрямую, не через стек уровней атласа — без крошек и «Назад». Смена модели между вопросами — с индикатором загрузки на холсте; кнопки «Ответить» и варианты доступны сразу (вопрос можно читать, пока грузится модель). Повторная загрузка той же модели берётся из кэша ядра. Только манифесты со `status: "ready"`: заглушки (сейчас `nucleus`) в тестах не используются.
- **Часть с `select: "each"`** (митохондрии в клетке, гранулы и ДНК в митохондрии): выделяется первый экземпляр — `listInstances(partId)[0]` ядра.
- После ответа — для вопроса с частью включить сноску выделенной части (теперь её название — уже не подсказка). Если показ только одной сноски ядро не умеет — сноски не включать, название есть в карточке.

### Итог
После «Завершить тест» (`POST /attempts/:id/complete`) панель показывает:
- «Тест пройден», крупно **«7 из 10»** и процент;
- оценочная фраза: ≥ 80 % «Отличный результат», 50–79 % «Неплохо, но есть что повторить», < 50 % «Стоит вернуться к атласу и повторить»;
- список вопросов: ✓/✗, короткий текст вопроса; у неверных — правильный ответ;
- кнопки: **«Пройти ещё раз»** (новая попытка), **«К списку тестов»**, текстовая «Открыть атлас».

Результат сохраняется в `localStorage` для карточки в списке; сохранённая попытка забывается.

Холст на итоге: модель теста, исходный вид, сноски включены.

### Ошибки и крайние случаи
| Ситуация | Поведение |
|---|---|
| Тест не найден (`404`) | «Тест не найден» + «К списку тестов» |
| Сеть / `5xx` при загрузке теста или старте | сообщение в панели + «Повторить» |
| Сеть / `5xx` при отправке ответа | сообщение под кнопкой, выбор сохраняется, «Ответить» снова активна |
| `409` на ответ (уже отвечено — двойной клик, вторая вкладка) | перечитать попытку, показать сохранённый результат этого вопроса |
| `409` попытка завершена | перейти к итогу (`GET /attempts/:id`) |
| Модель вопроса не загрузилась | вопрос всё равно можно ответить; на холсте — ошибка загрузки, как в атласе |
| Двойное нажатие «Ответить» | кнопка блокируется на время запроса |

## Идентификация пользователя

Авторизации нет. Связка «студент ↔ попытка» держится на браузере:

1. При первом заходе клиент создаёт случайный `clientId` (UUID) и хранит его в `localStorage` (`atlas.clientId`). Это не учётная запись, а метка браузера.
2. `POST /attempts` получает `clientId` и возвращает `attemptId`; сервер хранит попытку и все ответы в `quiz_db`.
3. Клиент запоминает `attemptId` для теста (`atlas.quiz.<quizId>.attemptId`). По нему после перезагрузки или возврата на страницу запрашивает попытку с сервера и продолжает.
4. Все запросы к попытке идут с заголовком `X-Client-Id`; если он не совпадает с `client_id` попытки, сервер отвечает `404` (как будто попытки нет). Так чужую попытку нельзя продолжить, даже зная её id.

Что это даёт: перезагрузка, закрытие вкладки, падение экземпляра Quiz — прохождение не теряется (состояние на сервере, а не в памяти экземпляра). Чего это не даёт: продолжить с другого браузера или устройства, после инкогнито или очистки данных сайта — там будет новый `clientId` и тест начнётся заново. Для анонимного режима это принятое ограничение; с появлением учётных записей `clientId` заменится на id пользователя, схема БД не изменится по сути.

`localStorage`, а не `sessionStorage`: незавершённый тест должен пережить закрытие вкладки.

## Технические требования к клиенту

- `QuizRunStore` (сервис на сигналах, область — фича `quiz`) управляет просмотрщиком через `ViewerService`, пока открыт `/quiz…`: `load`, `select(..., { fly: true })`, `setOptions({ labels: false, hover: false, exploded: false, isolate })`. Ядро не меняется.
- **`AtlasStore` не должен реагировать на события ядра вне `/atlas`.** Его эффекты в корневом сервисе слушают `openDetailRequest`, `loaded`, выбор — двойной клик по модели в тесте открыл бы детальный уровень и увёл в атлас. Ввести признак активного владельца просмотрщика (например, `ViewerService.owner: 'atlas' | 'quiz'`) и проверять его в эффектах `AtlasStore`.
- Клик по модели во время теста: если ядро всё же выбрало часть — `QuizRunStore` возвращает выбор вопроса (или снимает), без подлёта.
- `localStorage`: ключи `atlas.clientId`, `atlas.quiz.<quizId>.attemptId`, `atlas.quiz.<quizId>.lastResult` (`{ score, total, completedAt }`); чтение и запись в `try/catch`.
- Цвета «верно» / «неверно» — новые токены `success`, `success-bg`, `danger`, `danger-bg` в `styles/_tokens.scss` (контраст текста ≥ 4.5:1).
- Компоненты панели — в `features/quiz/ui/` как presentational (`quiz-list`, `question-card`, `answer-feedback`, `quiz-result`); smart — страницы фичи.

## Техдолг (после показа)

- Вопрос «Найдите на модели»: ответ кликом по части (`partId`) — меняет контракт ответа.
- Вопрос со вводом текста: список допустимых ответов + нормализация (регистр, «ё», пробелы).
- Режим экзамена (результаты только в конце), таймер, случайный порядок вопросов и вариантов.
- Частичные баллы за «несколько ответов».
- Мобильная версия экрана тестов.
- Точная ссылка «Открыть в атласе» на часть (`/atlas/animal-cell?select=<partId>`) — нужен параметр выбора в маршруте атласа.
