# Сценарий показа

Пошаговая демонстрация всех компонентов стенда: что сделать, какой командой и что должно быть видно. Длительность — 15–20 минут. Архитектура и описание компонентов — `docs/lab/architecture.md`, запуск и учётные данные — `deploy/README.md`.

Команды — для PowerShell из папки `deploy`. В Windows PowerShell 5.1 `curl` — это псевдоним `Invoke-WebRequest`, поэтому везде `curl.exe`.

## Подготовка (до показа, ~10 минут)

1. Чистый запуск:
   ```
   cd deploy
   docker compose down -v
   docker compose up -d --build
   ```
2. Через ~40 с — `node smoke.mjs`: все строки `OK`, код выхода 0. Smoke проходит тест, поэтому в аналитике будут первые данные — это нормально (или сделать `down -v` / `up` ещё раз, если нужна пустая аналитика для шага «пустое состояние»).
3. Открыть вкладки браузера и войти (логины и пароли — `deploy/README.md`):
   - приложение — http://localhost:8080
   - Consul — http://localhost:8500/ui
   - RabbitMQ — http://localhost:15672 (`atlas` / `change-me-rabbit`)
   - MinIO — http://localhost:9001 (`atlas-minio` / `change-me-minio-secret`)
4. Терминал в `deploy`, в браузере приложения открыты DevTools → Network.

## 1. Обзор: компоненты и данные атласа

| Действие | Что видно |
|---|---|
| Consul UI → Services | `catalog`, `quiz`, `analytics`, `gateway` (и `consul`) — зелёные, по одному экземпляру. В карточке экземпляра — IP контейнера и health check `/health` |
| Приложение → «Атлас» | 3D-клетка, справа состав. В Network: `/api/catalog/manifests/animal-cell` и `/api/catalog/entities/*` (данные из Catalog → `catalog_db`), `/models/animal-cell/v1/animal-cell.glb` (модель из MinIO через gateway) |
| Кликнуть на ответ `manifests/animal-cell` → Headers | `X-Instance` — какой экземпляр Catalog ответил, `X-Gateway-Instance` — gateway |
| Двойной клик по митохондрии (или «Подробнее» → детальная модель) | загрузка детальной модели митохондрии с индикатором; манифест — снова из Catalog |
| MinIO Console → Buckets → `models` | 4 файла `.glb`: их загрузил Catalog при старте (синхронизация при каждом старте) |

Что сказать: клиент ходит только на gateway (один origin), gateway маршрутизирует `/api/catalog` на Catalog по адресам из Consul, `/models` — в MinIO.

## 2. Тест → прямая связь Quiz → Catalog → брокер → аналитика

| Действие | Что видно |
|---|---|
| «Тесты» → «Строение органоидов» → «Начать» | загружается модель митохондрии, вопрос «Что выделено на модели митохондрии?»: камера подлетает к части, остальное приглушено, сносок нет |
| Клик и двойной клик по модели | ничего не выбирается, в атлас не уводит |
| Выбрать вариант → «Ответить» | плашка «Верно/Неверно», верный вариант помечен, сноска выделенной части, **карточка органоида** — Quiz получил её из Catalog напрямую по REST (адрес из Consul) |
| Ответить «Не знаю» на следующий вопрос | засчитано неверным, показан верный ответ |
| Пройти тест до конца | итог «N из 10» |
| `docker compose logs quiz --since 5m` | строки `Catalog entity "…" fetched from 172.x.x.x:8080` — адрес экземпляра Catalog из Consul |
| RabbitMQ → Exchanges → `quiz.events` | график входящих сообщений: `AnswerSubmitted` на каждый ответ, `TestCompleted` в конце |
| RabbitMQ → Queues → `analytics.quiz-events` | сообщения прошли через очередь (Message rates), сейчас 0 в очереди |
| Приложение → «Аналитика» | сводка (завершено попыток, средний результат, всего ответов, доля верных, время последнего события), «Самые трудные органоиды», таблица по вопросам с фильтром по тесту |

Можно открыть «Аналитику» во второй вкладке рядом с тестом: она обновляется раз в 10 с, видно, как приходят ответы.

## 3. Масштабирование

```
docker compose up -d --scale quiz=3
```

| Действие | Что видно |
|---|---|
| Consul UI → `quiz` (через ~20 с) | 3 экземпляра, все зелёные |
| `1..6 \| % { (curl.exe -si http://localhost:8080/api/quiz/quizzes \| Select-String '^x-instance').Line }` | три разных `x-instance` по кругу (RoundRobin) |
| Пройти пару вопросов теста | работает: попытка хранится в `quiz_db`, а не в памяти экземпляра, поэтому соседние запросы могут обслуживать разные экземпляры |

Catalog масштабируется так же: `docker compose up -d --scale catalog=2` → в логах Quiz обращения к разным адресам Catalog.

## 4. Отказ экземпляра

При трёх экземплярах Quiz (шаг 3):

```
docker ps --filter name=atlas-quiz --format "{{.Names}}"
docker stop atlas-quiz-2
```

| Действие | Что видно |
|---|---|
| Сразу после `stop` продолжить тест в браузере | ошибок нет: gateway повторяет `GET` на другом экземпляре, пассивная проверка выводит упавший из ротации |
| Consul UI → `quiz` | остановленный экземпляр снял регистрацию — осталось 2 |
| `node smoke.mjs` во время остановки (опционально) | все `OK` |

Проверено при подготовке: 100 запросов подряд во время `docker stop` одного из трёх экземпляров — 100 × `200`, параллельный `smoke.mjs` прошёл.

Вернуть: `docker compose up -d --scale quiz=1`.

## 5. Отказ Analytics: события копятся в брокере

```
docker compose stop analytics
```

| Действие | Что видно |
|---|---|
| Consul UI | `analytics` пропал / красный |
| Пройти тест (или `node smoke.mjs` — последние проверки упадут, это ожидаемо) | тест проходится как обычно: Quiz не зависит от Analytics |
| RabbitMQ → Queues → `analytics.quiz-events` | **Ready > 0** — сообщения копятся (например, 22 после двух попыток smoke) |
| «Аналитика» в приложении | если экран уже был открыт — «не удалось обновить — показаны последние данные»; при новом открытии — «Не удалось загрузить аналитику» и «Повторить» |
| `docker compose start analytics` | через 10–15 с очередь пуста, «Аналитика» учла все ответы |

## 6. Отказ Catalog: деградация, а не ошибка

```
docker compose stop catalog
```

| Действие | Что видно |
|---|---|
| Ответить на вопрос в тесте **в течение минуты** после остановки | карточка ещё есть: кэш сущностей в памяти Quiz (TTL 60 с) |
| Подождать минуту, ответить на вопрос | ответ проверяется, плашка «Верно/Неверно» есть, вместо карточки — «Описание сейчас недоступно»; в логе Quiz `WARN Catalog unavailable…` |
| Обновить страницу атласа | атлас без Catalog не открывается: окно «Не удалось загрузить данные атласа» с кнопкой «Повторить» (данные атласа — в Catalog, зависимость явная) |
| `docker compose start catalog` → «Повторить» в атласе | через ~10–20 с карточки в тесте и атлас снова работают |

## 7. Dead-letter queue

| Действие | Что видно |
|---|---|
| RabbitMQ → Exchanges → `quiz.events` → Publish message: Routing key `quiz.answer.submitted`, Payload `{"foo":1}` → Publish | «Message published» |
| Queues → `analytics.quiz-events.dlq` | 1 сообщение; Get messages — это `{"foo":1}` |
| `docker compose logs analytics --since 1m` | `Invalid message -> DLQ: …` |
| «Аналитика» | числа не изменились, сервис работает |

Что сказать: невалидное сообщение не теряется и не блокирует очередь — Analytics отклоняет его (`reject` без повтора), RabbitMQ перекладывает его в DLQ через `analytics.dlx`. Повторная доставка валидного события с тем же `eventId` статистику не меняет (идемпотентность по `eventId`, покрыто тестами).

## 8. Восстановление инфраструктуры (если спросят)

`docker compose restart postgres` (или `rabbitmq`, `consul`, `minio`) → через 5–20 с `node smoke.mjs` снова зелёный без перезапуска сервисов: подключения переустанавливаются с ретраями, регистрация в Consul повторяется каждые 30 с.

Проверено при подготовке (время до зелёного smoke): postgres 9 с, rabbitmq 16 с, consul 6 с, minio 5 с, gateway 6 с, catalog 7 с, quiz 13 с, analytics 15 с, web 2 с.

## Шпаргалка: требование ТЗ → что показать

| Требование | Чем закрыто | Шаг |
|---|---|---|
| Фронтенд на Angular | экраны «Атлас», «Тесты», «Аналитика» | 1, 2 |
| ≥ 2 микросервиса на разных языках | Catalog (C#), Quiz (TypeScript/NestJS), Analytics (Python/FastAPI) | 1, 2 |
| Прямая связь микросервисов | Quiz → Catalog по REST, адрес из Consul (карточка органоида; логи Quiz) | 2, 6 |
| Связь через брокер | Quiz → RabbitMQ `quiz.events` → Analytics | 2, 5, 7 |
| БД, ≥ 5 проработанных сущностей | PostgreSQL: 5 таблиц `catalog_db`, 6 `quiz_db`, 3 `analytics_db` (ER — `architecture.md`; `docker compose exec postgres psql -U postgres -d quiz_db -c '\dt'`) | — |
| Consul | регистрация, health checks, вывод из ротации; адреса для gateway и Quiz | 1, 3, 4 |
| API Gateway | YARP: маршруты, балансировка, отказ экземпляра без ошибок | 1, 3, 4 |
| Высокая нагрузка / отказоустойчивость | масштабирование, отказ экземпляра, накопление очереди, деградация, DLQ | 3–7 |
