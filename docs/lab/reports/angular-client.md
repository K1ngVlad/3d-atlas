### 1.4 — атлас через Catalog

- `angular.json`: конфигурация сборки `assets` (`fileReplacements`), `ng serve` по умолчанию с `proxyConfig: projects/app/proxy.conf.json`, конфигурация `serve:assets` без прокси. Docker-сборка (`ng build --configuration production`) — `api`.
- `package.json`: скрипт `start:assets` (`ng serve --configuration assets`) — атлас без бэкенда.
- `HttpStructureRepository`: `GET /api/catalog/manifests/{id}` + `parseManifest`, `GET /api/catalog/entities/{id}` (`404` → `null`), `manifestExists` через кэш `getManifest`. Кэш промисов; окончательные `404` кэшируются, сетевые ошибки / `5xx` — нет (иначе «Повторить» не ходил бы в сеть).

### 2.3 — экран тестов
- **Владелец просмотрщика:** `ViewerService.owner: 'atlas' | 'quiz' | null`. Ставит его `ViewerHostComponent` (input `owner`) при прикреплении ядра, снимает при уничтожении. Эффекты `AtlasStore` (`openDetailRequest`, `loaded`, выбранная сущность) работают только при `owner === 'atlas'`; владелец читается через `untracked`, чтобы смена владельца не перезапускала эффекты со старыми событиями.
- `ViewerHostComponent` и `LabelLayerComponent` больше не внедряют `AtlasStore`: получают данные через `input()` и отдают события через `output()`; атлас передаёт их со страницы. У сносок добавлены `only` (сноска одной части) и `interactive`.
- `data-access`: `QUIZ_REPO` + `HttpQuizRepository` (`X-Client-Id` на запросах к попытке), `ClientIdService` (`atlas.clientId`, `try/catch`, при ошибке — UUID на сеанс; запасной UUID без `crypto.randomUUID` — для открытия не по localhost), `QuizProgressStorage` (`atlas.quiz.<id>.attemptId`, `atlas.quiz.<id>.lastResult`).
- Токены `success`, `success-bg`, `danger`, `danger-bg` (контраст 5.5–6.5 : 1, посчитано по WCAG); общие классы кнопок/надзаголовка/скелетона — `styles/_controls.scss`.
- Маршруты: `/quiz` → `QuizShellComponent` (холст + панель) с дочерними `''` (список) и `:quizId` (прохождение). Холст общий — модель не перезагружается при переходе из списка в тест.
- `QuizCanvas` (область — оболочка `/quiz`): загрузка модели вопроса с индикатором и ошибкой как в атласе, выбор части с подлётом и изоляцией, `select: "each"` → `listInstances(partId)[0]`, сноски/наведение/расслоение выключены, клик по модели откатывает выбор к выбору вопроса без подлёта, «Сбросить вид», после ответа — сноска только выделенной части, на итоге — все сноски.
- `QuizRunStore` (область — страница прохождения): старт / продолжение попытки с первого неотвеченного, ответ, «Не знаю» (пустой `optionIds`), обратная связь, «Дальше» / «Завершить тест», итог, «Пройти ещё раз»; клавиши `1`–`9` и `Enter`.
- Presentational: `features/quiz/ui/` — `quiz-list`, `question-card` (с прогрессом), `answer-feedback`, `quiz-result`.
- Состояния из таблицы «Ошибки и крайние случаи»: `404` теста; сеть/`5xx` при загрузке и старте («Повторить»); сеть при ответе (сообщение под кнопкой, выбор сохраняется); `409` на ответ (перечитать попытку, показать сохранённый результат) и `409` «попытка завершена» (итог); ошибка модели; блокировка кнопки на время запроса. Дополнительно: `404` на ответ/завершение (попытку не найти — чужой `X-Client-Id`) → «Попытка не найдена… Начните заново», ключ забывается.

## Отклонения

- Страница прохождения и список — дочерние маршруты общей оболочки `QuizShellComponent`, а не две независимые страницы: иначе просмотрщик пересоздавался бы при переходе из списка в тест.
- `ViewerHostComponent` и `LabelLayerComponent` отвязаны от `AtlasStore` (inputs/outputs) — без этого их нельзя переиспользовать в тестах. Поведение атласа не изменилось.
- «Открыть в атласе» ведёт на модель вопроса (`/atlas/animal-cell` или `/atlas/animal-cell/<детальный манифест>`), а не на часть — точная ссылка в техдолге спецификации.
- Ответы, восстановленные из попытки (`GET /attempts/{id}`), показываются без карточки органоида: в ответе попытки нет сущности.
- Отступ модели от правой панели ядро применяет только при подлёте к части; при исходном виде модель центрируется по всему холсту — так же и в атласе (поведение ядра, не регрессия; ядро в этой работе не меняется).

## Предлагаемые записи для `docs/decisions.md`

| Решение | Почему |
|---|---|
| Владелец просмотрщика — `ViewerService.owner` (`'atlas' \| 'quiz'`), ставит холст при прикреплении; эффекты `AtlasStore` проверяют его через `untracked` | Корневой `AtlasStore` слушает события ядра; без владельца двойной клик в тесте открыл бы детальный уровень атласа |
| `ViewerHostComponent` и `LabelLayerComponent` получают данные через `input()`, не через `AtlasStore` | Один холст на атлас и тесты (Т1) |
| Раздел `/quiz` — оболочка с холстом и дочерними маршрутами списка и прохождения | Просмотрщик не пересоздаётся между списком и тестом; кэш моделей ядра переиспользуется |
| В ядро из `QuizCanvas` уходят только изменившиеся опции вида | Повторный `exploded: false` ядро считает выходом из расслоения и возвращает камеру |
| `HttpStructureRepository` кэширует только окончательные ответы (`200`, `404`); сеть/`5xx` из кэша убираются | «Повторить» после сбоя Catalog должен снова ходить в сеть |

## Замечания к контракту (`contracts.md` не менялся)

1. **Форма `entity` в ответе `POST /attempts/{id}/answers`:** `{ id, title, summary }` — не сказано, строки это или `{ ru }`, как в `EntityContent` Catalog. Клиент принимает оба варианта; лучше зафиксировать строки.
2. **Коды `409`:** различаются по смыслу («уже отвечено» / «попытка завершена»), но код в теле `error` не задан. Клиент в обоих случаях перечитывает попытку и решает по `completedAt` — работает, но стоит зафиксировать коды (например, `already_answered`, `attempt_completed`).
3. **`GET /attempts/{id}`** не возвращает сущность по ответам — восстановленные ответы без карточки органоида. Для минимальной версии достаточно.
4. **`X-Client-Id` на `POST /attempts`:** контракт требует его только для запросов к попытке; клиент шлёт его и здесь (вместе с `clientId` в теле) — сервис должен игнорировать/допускать.
5. **Числа в Analytics:** не указано, `avgScorePct`/`correctRatePct` — дробные или целые (0–100). Клиент округляет; `lastEventAt` — ISO-строка или `null` (как понял клиент).
6. В вопросах Quiz нет `entityId` — для вопросов без ответа клиент не может показать органоид (не требуется спецификацией).
