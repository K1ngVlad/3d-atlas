# Этап 2. Quiz Service + экран тестов (20–22.11)

Прочитай перед началом: `docs/lab/README.md`, `docs/lab/contracts.md` (Quiz, Consul, Клиент), **`docs/lab/quiz-ux.md` (экран тестов — источник истины для поведения)**, `docs/02-ux-spec.md` (общий стиль), `docs/03-frontend-architecture.md` (smart/presentational, сигналы, репозитории).

**Результат этапа:** на экране «Тесты» (модель слева, панель теста справа) можно выбрать тест, пройти его — в том числе вопросы «Что выделено на модели?» и вопросы по детальным моделям — и увидеть итог. После каждого ответа показывается описание органоида, которое Quiz получает из Catalog напрямую (адрес из Consul). Событий в брокер пока нет — они на этапе 3, но место их публикации уже выделено.

## Задачи

### 2.1 Quiz: данные
- [x] Prisma-схема: 6 моделей по `contracts.md`; миграция; `prisma migrate deploy` в entrypoint контейнера.
- [x] `prisma/seed/quizzes.json` по разделу «Начальные данные» контракта (два теста: по клетке и по детальным моделям; вопросы «Что выделено?», `single`, `multiple`). Проверки seed из контракта; ошибка → падение старта с понятным сообщением. **Пометить в отчёте, что тексты нужно проверить автору.**
- [x] Тест seed: каждый `part_id` существует в `projects/app/public/manifests/<manifest_id>.json`; каждый `entity_id` — в `content/entities`; `manifest_id` вопросов — только манифесты со `status: "ready"`.
- [x] Загрузка seed при старте, если `quizzes` пуста.

### 2.2 Quiz: API и логика
- [x] Эндпоинты из `contracts.md`. Признак `is_correct` никогда не уходит клиенту до ответа на этот вопрос.
- [x] Проверка ответа по правилам контракта (`single` / `multiple`, пустой ответ = «Не знаю», `400` / `409`).
- [x] Заголовок `X-Client-Id` на запросах к попытке: не совпадает или отсутствует → `404` (контракт).
- [x] `complete`: подсчёт по контракту, идемпотентно.
- [x] **Клиент Catalog** (`CatalogClient`): адрес через Consul (`/v1/health/service/catalog?passing=true`, список на 5 с, по кругу), таймаут 2 с, кэш сущностей в памяти с TTL 60 с. Ошибка → `entity: null` и предупреждение в лог, не `5xx`.
- [x] Точка расширения для событий: `QuizEventsPublisher` с `answerSubmitted(...)` и `testCompleted(...)`, вызываются **после** коммита; на этом этапе — реализация-заглушка (лог). Этап 3 подставит RabbitMQ.
- [x] Тесты (Jest): `multiple` — верно только при точном совпадении множества; пустой ответ — неверно; `409` на повторный ответ; `404` при чужом `X-Client-Id`; `entity: null` при недоступном Catalog (мок); `complete` идемпотентен.

### 2.3 Клиент: экран тестов — по `docs/lab/quiz-ux.md`
- [x] **Сначала:** владелец просмотрщика (`ViewerService.owner`) и проверка его в эффектах `AtlasStore` — раздел «Технические требования к клиенту» спецификации (иначе двойной клик по модели в тесте откроет детальный уровень атласа). Проверить, что атлас работает как раньше (`atlas.store.spec.ts`).
- [x] `data-access/repositories/quiz-repository.ts`: интерфейс + `QUIZ_REPO` + `HttpQuizRepository`; `clientId`, `X-Client-Id` и ключи `localStorage` — по спецификации.
- [x] Токены `success`, `success-bg`, `danger`, `danger-bg` в `styles/_tokens.scss` (контраст текста ≥ 4.5:1).
- [x] `/quiz` — список тестов с тремя состояниями карточки; модель на холсте без выбора.
- [x] `/quiz/:quizId` — `QuizRunStore`: старт / продолжение попытки, вопрос, ответ, «Не знаю», обратная связь, итог; управление холстом (сноски / наведение / расслоение / выбор кликом выключены; «Что выделено?» — выбор части с подлётом и изоляцией; вопросы по другим манифестам — загрузка модели с индикатором; часть с `select: "each"` — первый экземпляр через `listInstances`).
- [x] Presentational-компоненты в `features/quiz/ui/`: `quiz-list`, `question-card`, `answer-feedback`, `quiz-result`.
- [x] Все состояния из таблицы «Ошибки и крайние случаи» спецификации.
- [x] Тесты `QuizRunStore` на моке репозитория и `ViewerService`: продолжение попытки с первого неотвеченного; `409` на ответ → показан сохранённый результат; «Не знаю» отправляет пустой `optionIds`.

## Проверка

Выполнить на запущенном стеке; в «Отчёт» — результат каждого пункта.

1. `docker compose up -d --build`; `http://localhost:8080/quiz` — два теста, на холсте клетка.
2. Пройти оба теста целиком (во втором — переходы между моделями клетки, митохондрии и Гольджи с индикатором загрузки; у гранул/ДНК выделяется один экземпляр): вопросы «Что выделено?» — камера подлетает к части, остальное приглушено, сносок нет; клик и двойной клик по модели ничего не выбирают и не уводят в атлас; после ответа — подсветка вариантов, плашка «Верно/Неверно», карточка органоида; «Не знаю» засчитывается неверным и показывает ответ; итог совпадает с числом верных.
3. Вопрос `multiple`: выбрать часть верных → «Неверно», невыбранные верные помечены.
4. Обновить страницу посреди теста → продолжение с того же вопроса. В списке — «Продолжить (N из M)». После завершения — «Последний результат».
5. `curl` тела `GET /api/quiz/quizzes/{id}` — нет `isCorrect`. `curl GET /api/quiz/attempts/{id}` без `X-Client-Id` или с чужим → `404`.
6. `docker compose stop catalog` → ответить: проверка работает, вместо карточки «Описание сейчас недоступно». `docker compose start catalog` → карточка снова есть.
7. `--scale quiz=2` → пройти тест: запросы идут на разные экземпляры (`X-Instance`), прохождение не ломается. `--scale catalog=2` → в логах Quiz обращения к разным адресам Catalog.
8. Вернуться в атлас после теста — атлас работает как раньше (выбор, «Подробнее», расслоение).
9. `smoke.mjs` дополнен: создать попытку, ответить на все вопросы (часть верно, часть пустым ответом), завершить, проверить `score`.
10. Тесты Quiz и клиента проходят; `npm run lint` чистый.
11. Коммиты по задачам, **`git push`** выполнен.
