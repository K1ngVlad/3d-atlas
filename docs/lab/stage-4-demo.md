## Задачи

### 4.1 Запуск с нуля и отказоустойчивость
- [ ] `docker compose down -v` → `up -d --build` на чистых томах → всё поднимается без ручных шагов, seed отрабатывает.
- [ ] Порядок старта не важен: перезапуск любого одного контейнера (включая `postgres`, `rabbitmq`, `consul`) → система восстанавливается без перезапуска остальных (ретраи подключений, повторная регистрация в Consul).
- [ ] **Отказ экземпляра без ошибок у пользователя.** После остановки экземпляра gateway ещё ~5–12 с шлёт на него запросы (пока Consul не пометит его `critical`). Включить в YARP пассивные проверки здоровья (`HealthCheck.Passive`, политика `TransportFailureRate`, `ReactivationPeriod` ~10 с) и повтор идемпотентных `GET` на другой экземпляр, чтобы сценарий «Отказ экземпляра» проходил без `502`.
- [ ] `deploy/smoke.mjs` проходит целиком.

### 4.3 Сценарий показа — `docs/lab/demo.md`
Пошагово, с командами и тем, что должно быть видно. Каждый шаг выполнить и отметить.
- [ ] **Обзор:** приложение → атлас клетки (данные из Catalog, модель из MinIO, вкладка Network); Consul UI — сервисы зелёные.
- [ ] **Тест и аналитика:** пройти тест (включая вопрос «Что выделено?» и вопрос по митохондрии) → карточки органоидов (Quiz → Catalog напрямую) → экран аналитики обновился (Quiz → RabbitMQ → Analytics).
- [ ] **Масштабирование:** `docker compose up -d --scale quiz=3` → три экземпляра в Consul; `curl -si localhost:8080/api/quiz/quizzes` несколько раз — разные `X-Instance`.
- [ ] **Отказ экземпляра:** `docker stop <один quiz>` → он уходит из Consul, тест продолжает проходиться без ошибок (попытка в БД, а не в памяти экземпляра).
- [ ] **Отказ Analytics:** остановить → пройти тест → сообщения в очереди → запустить → обработаны.
- [ ] **Отказ Catalog:** остановить → тест работает без карточек органоидов (деградация, а не ошибка).
- [ ] **Dead-letter:** битое сообщение → DLQ.
- [ ] Шпаргалка «Требование ТЗ → что показать» (таблица из `docs/lab/README.md` + номер шага сценария).
