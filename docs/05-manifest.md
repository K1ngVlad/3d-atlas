# Манифест сцены и подключение моделей

## Три слоя данных

1. **Модель** (`projects/app/public/models/<id>/v<N>/<file>.glb`) — только геометрия и материалы. Не правим, кроме оптимизации и, при необходимости, разделения частей в Blender.
2. **Манифест** (`projects/app/public/manifests/<id>.json`) — как показывать модель: какие узлы что означают, кликабельность, сноски, расслоение, детальные переходы.
3. **Контент** (`projects/app/public/content/entities/<entity>.json`) — тексты, привязанные к сущности (`mitochondrion`), а не к модели. Одна сущность может встречаться в нескольких моделях.

Позже Catalog Service будет хранить и отдавать ровно эти же структуры: формат манифеста — будущий контракт API.

## Пример манифеста

```json
{
  "schemaVersion": 1,
  "id": "animal-cell",
  "entity": "animal-cell",
  "model": { "url": "models/animal-cell/v1/cell.glb", "scale": 1, "upAxis": "y" },
  "camera": { "fit": "auto", "minDistance": 0.5, "maxDistance": 20 },
  "defaults": { "pick": "block", "hoverable": true },
  "parts": [
    {
      "id": "membrane",
      "entity": "plasma-membrane",
      "nodes": ["Cell_Membrane"],
      "pick": "pass",
      "material": { "opacity": 0.35 },
      "explode": { "order": 0, "stay": true }
    },
    {
      "id": "mito",
      "entity": "mitochondrion",
      "nodes": ["Mitochondrion"],
      "pick": "select",
      "label": { "anchor": "auto" },
      "explode": { "order": 5 },
      "detail": "mitochondrion"
    },
    {
      "id": "ribosomes",
      "entity": "ribosome",
      "nodes": ["Ribosomes"],
      "pick": "select",
      "render": { "instanced": true }
    }
  ],
  "ignore": [{ "match": "^Light|^Camera" }],
  "source": {
    "author": "…",
    "url": "https://…",
    "platform": "Sketchfab",
    "license": "CC-BY-4.0",
    "modified": true
  }
}
```

## Поля

| Поле | Описание |
|---|---|
| `schemaVersion` | версия формата; при несовместимых изменениях растёт, загрузчик умеет мигрировать старые |
| `status` | `"ready"` или `"stub"` (заглушка детального уровня на модели родителя) |
| `include` | селектор узлов, которые отображаются; остальные скрыты. По умолчанию — вся модель |
| `id` | идентификатор сцены, используется в маршрутах и в `detail` |
| `entity` | сущность всей модели (описание по умолчанию в панели) |
| `model.url`, `scale`, `upAxis` | файл и нормализация масштаба и осей |
| `camera` | начальная камера: `"fit": "auto"` или явные `position` / `target`, ограничения дистанции |
| `defaults` | значения по умолчанию для всех частей |
| `parts[]` | описанные части модели |
| `parts[].nodes` | селектор узлов: строка, массив строк или `{ "match": "<regex>" }`. Узел выбирается **вместе со всем поддеревом**: `["Nucleus"]` захватывает оболочку, поры, ядрышко и хроматин. Часть может состоять из нескольких узлов |
| `parts[].pick` | поведение при клике: `"select"` — выбирается; `"pass"` — луч проходит насквозь к тому, что за ней; `"block"` — луч останавливается, ничего не выбирается. См. «Выбор по клику» |
| `parts[].select` | `"whole"` (по умолчанию) — часть выбирается целиком; `"each"` — экземпляры выбираются по одному: если селектор нашёл **один** узел — экземпляры его прямые потомки, если **несколько** — каждый найденный узел. См. «Повторяющиеся объекты» |
| `parts[].hoverable` | подсвечивается ли при наведении |
| `parts[].label` | `anchor`: `"auto"` — точка **на поверхности части**, выбранная ядром из заранее вычисленных точек (см. «Якоря сносок»), или `[x,y,z]` в координатах модели — когда автоматический выбор не устраивает (координаты копируются в `?debug=manifest`); `hidden: true` — без сноски; для `select: "each"` — `instance: "<узел>"` (сноска у одного экземпляра, по умолчанию у первого) или `each: true` (у каждого) |
| `parts[].explode` | `order`, `stay`, опционально `direction`, `offset` |
| `parts[].detail` | `id` манифеста детальной модели |
| `parts[].focus` | для детальной модели, открытой из родителя: какую часть подсветить и к какой подлететь (например, шероховатый ЭПР в модели всего ЭПР) |
| `parts[].material` | переопределения: `opacity`, `color`, `emissive`, `transmission` (0 — отключить дорогой проход прозрачности), `alphaMode`: `"OPAQUE"` / `"BLEND"` (как в glTF; `OPAQUE` — `transparent = false`, `depthWrite = true`). Применяются к клонам материалов во время работы — файл модели не меняется |
| `parts[].render.instanced` | `true` или селектор: какие узлы поддерева с одинаковой геометрией объединить в `InstancedMesh` (рибосомы) |
| `ignore[]` | узлы, которые не отображать или не учитывать |
| `source` | автор, ссылка, площадка, лицензия, признак изменения — обязательно; `technical` — описание технических изменений (сжатие), если модель не адаптировалась |

Ссылка `detail` может нести фокус: `"detail": { "id": "endoplasmic-reticulum", "focus": "rough-er" }`.

## Контент сущности

```json
{
  "id": "mitochondrion",
  "kind": "organelle",
  "title": { "ru": "Митохондрия" },
  "summary": { "ru": "Двумембранный органоид…" },
  "sources": ["…"]
}
```

Тексты пишутся по учебникам и проверяются медуниверситетом. Тексты аннотаций со Sketchfab не копируются.

## Правила разумных значений по умолчанию

- Якорь сноски — точка на поверхности части (см. «Якоря сносок»).
- Порядок расслоения — порядок в массиве `parts`.
- Камера — вписать модель целиком.
- Неописанные узлы — фон: видны, не кликабельны, без сносок.
- Минимальный рабочий манифест — `model` + `parts` с `id`, `entity`, `nodes`.

## Детальные уровни: механизм делается сразу, модели добавляются потом

Принцип: переходы между уровнями (поле `detail`, стек уровней, крошки, «Назад», восстановление состояния) реализуются и проверяются **до** появления настоящих детальных моделей. Добавление новой детальной модели — это только новые файлы (`.glb` + манифест + контент), без изменений кода.

### Заглушки

Пока настоящей детальной модели нет, её манифест — заглушка на модели родителя:

```json
{
  "id": "mitochondrion",
  "status": "stub",
  "model": { "url": "models/animal-cell/v1/animal-cell.glb" },
  "include": { "match": "^Mitochondrion\\.1_" },
  "parts": [ ... ]
}
```

- `include` — селектор узлов, которые вообще отображаются; всё остальное в модели скрыто. Без `include` отображается вся модель.
- `status`: `"stub"` | `"ready"`. Ядро и приложение обращаются с заглушкой как с обычным манифестом; статус нужен только для отладки и отчётов.
- Замена заглушки настоящей моделью: положить новый `.glb`, переписать манифест с тем же `id`, поменять `status` на `"ready"`. Манифест родителя не меняется.
- Если модель уже загружена (заглушка на той же модели, что родитель), повторная загрузка файла не нужна — ядро берёт её из кэша.

### `detail` указывает на несуществующий манифест

Часть ведёт себя как обычная: без кнопки «Подробнее», без значка лупы, двойной клик ничего не делает. В консоль — предупреждение с `id`. Поэтому в манифесте родителя можно сразу прописать все переходы.

## Повторяющиеся объекты

Несколько одинаковых органоидов в разных местах (три митохондрии, сотни рибосом на детальном уровне ЭПР) описываются **одной частью** с `"select": "each"`:

```json
{ "id": "mitochondria", "entity": "mitochondrion", "nodes": ["Mitochondria"],
  "select": "each", "label": { "instance": "Mitochondrion.1" }, "detail": "mitochondrion" }
```

- Экземпляры — прямые потомки узла `Mitochondria`: `Mitochondrion.1`, `.2`, `.3`. Каждый выбирается отдельно, с подлётом камеры к нему.
- Если повторы в модели не сгруппированы под общим узлом (частый случай в чужих и загружаемых моделях), селектор находит их по шаблону, и **каждый найденный узел** становится экземпляром:

  ```json
  { "id": "granules", "nodes": { "match": "^granule_\\d+$" }, "select": "each" }
  ```

  Шаблон должен находить сами узлы-объекты, а не их вложенные меш-узлы: `^granule_\d+$`, а не `^granule_` (иначе попадут и `granule_0001_..._0`).
- Описание, сущность и переход `detail` общие для всех экземпляров.
- Выбор — это пара `{ partId, instance }`; у `select: "whole"` `instance` пустой.
- Сноска по умолчанию одна (иначе сотни подписей на рибосомах).
- При расслоении экземпляры двигаются вместе, как одна часть.
- Для инстансированного рендера (`render.instanced`) экземпляр определяется по `instanceId` из raycast.

Когда использовать `whole`, а когда `each` — вопрос биологии, а не геометрии:
- `each` — самостоятельные одинаковые органоиды: митохондрии, лизосомы, рибосомы на детальном уровне;
- `whole` — одна структура из нескольких кусков: две центриоли образуют одну центросому; сегменты гладкого ЭПР — одна сеть; составной органоид на уровне родителя (ядро, шероховатый ЭПР вместе с рибосомами).

## Выбор по клику

Модель — дерево узлов, а манифест накладывает на него части. Чтобы клик выбирал «то, что пользователь видит как один объект»:

1. Луч собирает **все** пересечения по порядку удалённости (а не только первое).
2. Для каждого пересечения находим часть: идём от меша вверх по дереву до ближайшего узла, захваченного какой-либо частью. Узлы вне `include` игнорируются. Если ни одна часть не захватила узел — действует `defaults.pick`.
3. Смотрим `pick` этой части:
   - `select` — выбираем часть, стоп;
   - `pass` — пропускаем пересечение, идём к следующему;
   - `block` — стоп, ничего не выбрано.
4. Если пересечений не осталось — ничего не выбрано.

Отсюда правила разметки:

- **Составной органоид на уровне родителя выделяется целиком.** На уровне клетки часть `nucleus` захватывает узел `Nucleus` со всем поддеревом: клик по ядрышку, хроматину или поре выделяет ядро. Отдельные компоненты становятся выбираемыми только на детальном уровне, где у них свои части.
- **Полупрозрачные «наполнители»** (нуклеоплазма, матрикс), сквозь которые видно внутренние структуры, — `pass`, иначе они перехватывают клики. Выбрать их можно из списка «Состав».
- **Полупрозрачная плоскость среза** (цитоплазма), под которой видны нижние слои, — `select`: клик по «полу» показывает цитоплазму, а то, что видно сквозь неё, не выбирается случайно.
- **Неописанные непрозрачные объекты** — по умолчанию `block` (`defaults.pick`): клик по ним ничего не выбирает и не «пробивает» их к тому, что сзади.
- **Мелкий фон** — `pass`.
- **Наведение и выбор — разные вещи.** `hoverable: false` отключает только подсветку при наведении; `pick` по-прежнему решает, что делает клик и проходит ли луч. Для большой «подложки» (цитоплазма — плоскость среза) подсветка при каждом движении мыши по полу отвлекает: ей стоит `hoverable: false` при `pick: "select"` — луч останавливается на ней (то, что под срезом, не выбирается), клик показывает описание цитоплазмы, но пол не мигает.
- Список «Состав» в панели — всегда доступный способ выбрать любую часть, даже если её трудно задеть мышью.

## Сопоставление селекторов с узлами

- Селекторы сравниваются с **исходными именами узлов glTF** (`json.nodes[i].name`), а не с `Object3D.name`. `GLTFLoader` санитизирует имена (удаляет точки и другие служебные символы: `Sphere.005_8` → `Sphere005_8`) и добавляет суффиксы к дубликатам.
- Связь «Object3D → индекс узла glTF» берётся из `gltf.parser.associations`.
- Селектор по имени узла-обёртки захватывает и все его дочерние меши.

## Якоря сносок

Центр габаритов для якоря не годится: у протяжённых и полых частей он лежит вне части (центр шероховатого ЭПР, охватывающего ядро, приходится на ядро).

`anchor: "auto"`:
1. При загрузке манифеста ядро вычисляет для части 8–12 **точек-кандидатов на её поверхности** (выборка вершин методом дальнейшей точки; хранятся в координатах модели, поэтому следуют за расслоением). Для экземпляров `each` — свои кандидаты у каждого.
2. На кадре выбирается кандидат, который виден (в кадре, не закрыт) и ближе всего к экранному центру части. Смена кандидата — с гистерезисом: новый должен быть заметно лучше и оставаться лучше ~300 мс. Если закрыты все — остаётся текущий, сноска приглушается.
3. Покадровый raycast к частям не нужен — только проекция точек; проверка окклюзии кандидатов троттлится.

`anchor: [x, y, z]` — явная точка в координатах модели для случаев, когда автоматический выбор не устраивает. В `?debug=manifest` Shift+клик по модели копирует координаты точки поверхности в формате манифеста.

## Расслоение вместе с другой частью

`explode.with: "<partId>"` — часть не получает своей позиции в столбце, а смещается вместе с указанной (рибосомы едут вместе с шероховатым ЭПР).

## Валидация

- Схема на zod в `viewer-core/src/manifest`. Типы выводятся из схемы.
- При загрузке модели проверяется, что каждый селектор нашёл хотя бы один узел. Ошибка понятная: «узел `Cell_Membrane` не найден; похожие: `Cell_membrane_01`».
- Узел, попавший в две части, — предупреждение.
- `detail` должен указывать на существующий манифест.

## Процесс подключения новой модели

1. Скачать модель в glTF/GLB, проверить лицензию (CC BY / CC BY-SA допускают изменения; ND — только технические: сжатие, смена формата текстур).
2. Решить, нужен ли скрипт. **Если объекты модели уже разделены по смыслу — скрипт только сжимает, вся разметка в манифесте** (пример: `docs/models/mitochondrion.md`). Группировка, имена частей, повторы (`each` по шаблону), прозрачность (`material.alphaMode`) — задача манифеста. Скрипт нужен только для дефектов геометрии, которые манифест не исправит: склеенные меши, дубликаты, лишние объекты (пример: `docs/models/animal-cell.md`).
   Если нужны переименование или разделение мешей — скрипт `tools/prepare-<model>.mjs` по образцу `tools/prepare-animal-cell.mjs` (со встроенными проверками). Сжатие: `dedup` + `prune` + `meshopt` (+ KTX2 для текстур, `simplify` для тяжёлых мешей). **Не использовать `instance`** — он стирает имена инстансируемых узлов.
3. Получить дерево узлов: `npm run inspect -- out.glb` → JSON с именами, иерархией, габаритами и числом треугольников.
4. Написать манифест (вручную или с помощью Claude по выводу `inspect`), добавить контент сущностей.
5. Довести в отладочном режиме разметки (`?debug=manifest`): при наведении видны имена узлов, клик копирует имя, видны якоря, габариты и порядок расслоения; манифест перечитывается без пересборки.

## Будущее

Экран «Загрузка моделей» — визуальный редактор того же манифеста: загрузить `.glb`, увидеть дерево узлов, кликом сопоставить узлы с сущностями, поставить якоря, указать детальные модели. Изображения (микрофотографии) размечаются тем же форматом с координатами на картинке вместо узлов.
