# Принятые решения

Короткий журнал. Не пересматривать без новой причины; при пересмотре — дописать новую запись, а не стирать старую.

| # | Решение | Почему |
|---|---|---|
| 1 | Тема: обучающая платформа (атлас + тесты + аналитика), начиная с клетки | Ложится на ТЗ лабораторной, связана с НИР, есть запрос медуниверситета |
| 2 | Клиент на Angular, а не React | Требование ТЗ; Angular задаёт архитектуру (DI, сервисы), проще не смешивать UI и данные |
| 3 | 3D-ядро — отдельный проект на чистом TS, без Angular | В старом проекте react-three-fiber смешал рендер DOM и 3D; ядро переиспользуемо и тестируемо отдельно |
| 4 | three.js, а не Babylon.js | Опыт автора, наработки из атласа, всё нужное есть в экосистеме; смена движка съест время |
| 5 | Модель, манифест и контент — раздельные слои | Новые модели подключаются конфигом, без кода; основа для открытой системы и API Catalog |
| 6 | Явное сохранение состояния уровня (`ViewState`) | Без него при переходах меши «улетают», камера сбрасывается |
| 7 | Позиции расслоения всегда вычисляются из манифеста | Исключает накопление ошибок положения |
| 8 | Выбор одиночным кликом, переход двойным или повторным | На сенсорных экранах нет наведения; новичок не проваливается неожиданно на уровень ниже |
| 9 | Правая панель — только информация; настройки вида — в оверлее над холстом | Не перегружать панель; настройки нужны и при скрытой панели |
| 10 | Хлебные крошки + URL на каждый уровень | Ориентация при глубине больше двух; работает «назад» браузера и прямые ссылки |
| 11 | Мобильная версия: бургер + нижняя шторка с тремя точками остановки | Ограничение места; привычный паттерн |
| 12 | Шторка — свой компонент, а не Ionic / `MatBottomSheet` | Нужны точки остановки, жесты и связь с камерой (`setViewportInsets`) |
| 13 | Angular Material + CDK для стандартных элементов | Ближе всего к MUI, официальная поддержка, покроет будущие админские экраны |
| 14 | SCSS, токены через CSS custom properties | Темизация Material на SCSS; компоненты зависят только от токенов |
| 15 | Один детальный ЭПР с двумя частями вместо двух моделей | Биологически точнее, нет отдельной модели гладкого ЭПР |
| 16 | Сначала клиент на локальных JSON, бэкенд потом | Сроки; репозиторий за токеном DI делает подмену дешёвой |
| 17 | Бэкенд: Quiz на NestJS, одна СУБД PostgreSQL, Redis опционален, модели в MinIO | См. `docs/06-backend.md` |
| 18 | Система строится на одной модели клетки; детальные уровни сначала на заглушках, настоящие модели — по одной потом | Меньше риска «каши»; механизм переходов проверяется заранее, добавление модели не требует кода |
| 19 | Корневая модель — «Animal cell 2.0» (montanna, CC BY 4.0), подготовка скриптом, а не вручную в Blender | Воспроизводимо, со встроенными проверками; см. `docs/models/animal-cell.md` |
| 20 | Селекторы манифеста сопоставляются с исходными именами узлов glTF через `parser.associations` | `GLTFLoader` санитизирует `Object3D.name` |
| 21 | Не использовать `gltf-transform instance`; инстансинг — в ядре по `render.instanced` | `instance` стирает имена узлов |
| 22 | Режимы клика `pick: select / pass / block` вместо флага `pickable`; луч проходит по всем пересечениям | Полупрозрачные наполнители не должны перехватывать клики, а плоскость среза — должна |
| 23 | Иерархия узлов в подготовленной модели повторяет строение (Nucleus → компоненты, RoughER → мембрана + рибосомы); часть захватывает узел с поддеревом | Составной органоид на уровне родителя выделяется целиком, манифест короче и понятнее |
| 24 | Повторяющиеся органоиды — одна часть с `select: "each"` (экземпляры выбираются по одному, описание и переход общие) | Три митохондрии — три объекта, а не один; сотни рибосом не описываются поштучно |
| 25 | Центросома выбирается целиком (две центриоли), гладкий ЭПР — целиком (три сегмента) | Это одна структура из нескольких кусков |
| 26 | На уровне клетки шероховатый и гладкий ЭПР — две части с общим узлом `EndoplasmicReticulum` и одной детальной моделью (с фокусом) | В учебнике это два разных понятия; на детальном уровне видна их связь. Объединить в одну часть — одна строка манифеста |
| 27 | Удаляя объекты из модели, проверять их рендером: видимость в обычном виде **и** при подсветке/изоляции | Крупная «рибосома» сначала была сохранена как видимая заливка ядра, но при подсветке ядра оказалось, что она торчит сквозь ЭПР. Итог: удалена, цвет ядра компенсирован материалом нуклеоплазмы в скрипте |
| 28 | Постоянный кэш моделей на клиенте — Cache Storage в приложении (`ModelCacheService`), ядро получает модель через `ViewerConfig.fetchModel` | Мгновенные повторные открытия и работа без сети; ядро не зависит от хранилищ браузера; версия в пути делает кэш «навсегда» безопасным |
| 29 | Порядок после экрана атласа: сноски → расслоение → настоящая детальная модель → мобильная версия → кэш | Сначала то, что видно на демонстрации в медуниверситете; кэш почти незаметен при показе. Сноски раньше расслоения — расслоение потом проверяется сразу и на пикинге, и на подписях |
| 30 | Детальная митохондрия — «Mitochondria - Cell Organelles» (Vida Systems, CC BY-NC-ND 4.0), а не CC BY-модель CAPTAAINRO | Объекты уже разделены по смыслу (оболочка, кристы, матрикс, мтДНК, гранулы), 45 тыс. треугольников; модель CAPTAAINRO — 523 тыс. треугольников, куски без смысла, части различимы только по текстуре. ND соблюдается: в файле только технические изменения (CC 4.0, п. 2(a)(4)), разметка — в манифесте. NC: при коммерческом использовании модель заменить или получить разрешение автора |
| 31 | `select: "each"` с несколькими найденными узлами: экземпляр — каждый найденный узел | В загружаемых моделях повторы редко сгруппированы под общим узлом; поведение для одного узла (экземпляры — дети) не меняется |
| 32 | `material.alphaMode` в манифесте | В модели митохондрии у всех частей `BLEND` — непрозрачные кристы рисуются с ошибками сортировки и пропадают за оболочкой. Исправляется во время работы, без правки файла |
| 33 | Порядок подключения модели: скрипт — только для дефектов геометрии, всё остальное — манифест | Совпадает с будущей загрузкой моделей пользователями: программа должна принимать модель «как есть» и размечать её конфигом |
