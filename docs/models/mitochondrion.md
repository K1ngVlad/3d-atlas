## Структура модели (без изменений)

```
Sketchfab_model → 1a0174517c004da1a539b72e1cce0462.fbx → RootNode
├─ shell          оболочка: наружная и внутренняя мембраны одним объектом, вырез сверху
├─ cristae        кристы (складки внутренней мембраны)
├─ matrix         срез матрикса (плоскость в вырезе)
├─ dna_01 … dna_03            кольцевые мтДНК
└─ granule_0000 … granule_0006  гранулы матрикса
```

У каждого узла один вложенный узел с мешем (`shell` → `shell_TT_checker_512x512_UV_GRID_0`). Все меши используют один материал с текстурным атласом (название `TT_checker…` — наследие исходника, текстура настоящая).

## Особенности

- **Вес — в текстурах, не в геометрии.** Три PNG 4096² занимали 43 МБ из 44. После 2048² WebP — 2,4 МБ всего файла.
- **У материала `alphaMode: BLEND`**, ~31 % текселей полупрозрачные (оболочка, матрикс). Из-за этого непрозрачные кристы, ДНК и гранулы сортируются как прозрачные: в виде по умолчанию кристы почти не видны за оболочкой, при повороте — полосы. Решение — `material.alphaMode: "OPAQUE"` для `cristae`, `dna`, `granules` в манифесте (решение 32). Оболочка и матрикс остаются полупрозрачными, как задумал автор.
- **Повторы не сгруппированы**: ДНК и гранулы — отдельные узлы без общего родителя. Выбираются по одному через `{"match": "^dna_\\d+$"}` + `select: "each"` (решение 31).
- Оболочка — наружная и внутренняя мембраны одним объектом, поэтому часть `membranes` («Мембраны митохондрии»), а не «наружная мембрана», как в заглушке.

## Что делает скрипт

`node tools/prepare-mitochondrion.mjs <путь>/scene.gltf projects/app/public/models/mitochondrion/v1/mitochondrion.glb`

1. Проверяет, что это та самая модель: 45 639 треугольников, 13 мешей, все узлы из манифеста на месте.
2. `dedup`, `prune` (`keepLeaves: true`), текстуры → 2048² WebP (`sharp`), `meshopt`.
3. Проверяет, что изменения только технические: число треугольников, имена и родители всех узлов совпадают с исходником; все текстуры WebP не больше 2048².

Зависимости: `@gltf-transform/core`, `extensions`, `functions`, `meshoptimizer`, `sharp`.

Проверка результата: рендер исходника и сжатой модели с шести ракурсов. Различия (0,4–1,7 % пикселей заметно) — только в порядке отрисовки полупрозрачных треугольников, видимые детали не пропали.

## Части в манифесте

| Часть | Узлы | `pick` / `select` | Материал | Расслоение |
|---|---|---|---|---|
| `membranes` | `shell` | select | как в модели (BLEND) | вниз, порядок 1 |
| `cristae` | `cristae` | select | `OPAQUE` | на месте |
| `matrix` | `matrix` | **pass** (наполнитель; выбор из «Состава») | как в модели | вверх, порядок 1 |
| `dna` | `^dna_\d+$` | select, **по одной** | `OPAQUE` | вверх, порядок 2 |
| `granules` | `^granule_\d+$` | select, **по одной** | `OPAQUE` | вместе с `dna` |

Направления расслоения заданы явно (`direction`): оболочка центрирована относительно модели, радиальное направление для неё не определено. Подобрать точнее — на этапе 5.

## Что нужно от ядра

Модель подключается без правки файла, но выявила два пробела механизма (roadmap, этап 6): `select: "each"` для нескольких найденных узлов и `material.alphaMode`. Пока их нет, манифест уже загружается: ДНК и гранулы выбираются по одной, но экземпляры называются по вложенным меш-узлам; кристы рисуются с ошибками прозрачности.

## Открытые вопросы

- Тексты сущностей `mitochondrial-membranes`, `mitochondrial-matrix`, `mitochondrial-dna`, `mitochondrial-granule` — заглушки, уточнить у медуниверситета.
- Сущность `mitochondrial-outer-membrane` (из заглушки) больше не используется.
