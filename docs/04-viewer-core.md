# 3D-ядро `viewer-core`

Чистый TypeScript + three.js. Не знает об Angular, UI и предметной области. Получает манифест сцены, отображает модель, обрабатывает ввод на холсте и сообщает о событиях.

## Модули

```
projects/viewer-core/src/
├─ manifest/   # zod-схема, типы, разрешение селекторов узлов, валидация
├─ scene/      # загрузка glTF, сцена, свет, рендерер, рендер-цикл, dispose
├─ camera/     # camera-controls, подлёт (fitTo), сохранение и восстановление, insets
├─ picking/    # raycast (three-mesh-bvh), режимы pick (select/pass/block), hover/select
├─ highlight/  # визуальные состояния частей с плавными переходами: подсветка, выбор, приглушение, изоляция
├─ explode/    # расчёт целевых позиций и анимация расслоения
├─ labels/     # якоря, проекция в экранные координаты, видимость
├─ viewer.ts   # класс Viewer, собирает модули
└─ public-api.ts
```

## Публичный API (черновик)

```ts
export interface ViewerOptions {
  labels: boolean;
  exploded: boolean;
  hover: boolean;
  isolate: boolean;
}

export interface Selection {
  partId: string;
  instance?: string; // имя узла-экземпляра для частей с select: "each"
}

export interface ViewState {
  manifestId: string;
  camera: { position: Vec3; target: Vec3 };
  options: ViewerOptions;
  selection: Selection | null;
}

export type ViewerEvent =
  | { type: 'hover'; selection: Selection | null }
  | { type: 'select'; selection: Selection | null }
  | { type: 'open-detail'; partId: string; detailId: string } // двойной клик / повторный клик
  | { type: 'load-progress'; loaded: number; total: number }
  | { type: 'loaded' }
  | { type: 'error'; error: ViewerError };

export interface LabelPosition {
  partId: string;
  instance?: string; // имя узла-экземпляра для частей с select: "each"
  x: number; y: number;   // CSS-пиксели относительно холста
  visible: boolean;       // false, если якорь вне кадра или за камерой
  occluded: boolean;      // якорь закрыт непрозрачной геометрией
}

export interface Viewer {
  load(manifest: SceneManifest, opts?: { signal?: AbortSignal }): Promise<void>;
  preload(manifest: SceneManifest): Promise<void>;
  select(selection: Selection | null, opts?: { fly?: boolean }): void;
  hover(selection: Selection | null): void;
  listInstances(partId: string): string[];   // для «1 из 3» и кнопок ‹ ›
  setOptions(o: Partial<ViewerOptions>): void;
  setViewportInsets(i: { top?: number; right?: number; bottom?: number; left?: number }): void;
  resetCamera(): void;
  getViewState(): ViewState;
  restoreViewState(s: ViewState): void;
  getLabelPositions(): LabelPosition[];
  /** Точка поверхности модели под экранными координатами (координаты модели) — для `label.anchor` в ?debug=manifest. */
  pickSurface(clientX: number, clientY: number): Vec3 | null;
  on(listener: (e: ViewerEvent) => void): () => void;   // возвращает отписку
  // Сноски на каждом отрисованном кадре (не чаще). Пока сноски выключены
  // или якорей нет — пустой массив присылается один раз на переход, а не каждый кадр.
  onFrame(listener: (labels: LabelPosition[]) => void): () => void;
  resize(width: number, height: number, dpr: number): void;
  dispose(): void;
}

/** Загрузка файла модели. Ядро не знает, откуда берутся байты: сеть, кэш, тестовая заглушка. */
export type FetchModel = (
  url: string,
  opts: { signal?: AbortSignal; onProgress?: (loaded: number, total: number) => void },
) => Promise<ArrayBuffer>;

export interface ViewerConfig {
  fetchModel?: FetchModel;   // по умолчанию — обычный fetch с прогрессом
  // ... прочие настройки (фон, качество, debug)
}

export function createViewer(canvas: HTMLCanvasElement, config?: ViewerConfig): Viewer;
```

**Загрузка моделей — через `fetchModel`.** Ядро получает байты модели только через эту функцию и разбирает их `GLTFLoader.parse()` (с `MeshoptDecoder`). Своего `fetch`, IndexedDB, Cache Storage и т. п. в ядре нет. Реализацию с кэшированием подставляет приложение (`docs/03-frontend-architecture.md`, «Кэш моделей»); в тестах — заглушка. Точка расширения закладывается с первого прототипа, даже пока кэша нет: тогда кэш добавляется без изменений ядра.

Одна модель может использоваться несколькими манифестами (заглушки детальных уровней): ядро держит в памяти разобранные модели по `url` и не загружает их повторно в течение сеанса. Это кэш в памяти на время работы, он не заменяет постоянный кэш приложения.

Ядро не зависит от RxJS: события — простые колбэки. Обёртку в Observable / сигналы делает адаптер в приложении.

## Ключевые алгоритмы

### Выбор и приоритет зон
1. Raycast по мешам с BVH, **все** пересечения по удалённости.
2. Для каждого пересечения — часть, захватившая ближайший узел-предок меша (селектор части захватывает узел вместе с поддеревом; если узел захвачен несколькими частями, побеждает часть с более глубоким узлом).
3. `pick` части: `select` — результат; `pass` — к следующему пересечению; `block` — ничего не выбрано. Узлы без части — `defaults.pick`.
4. Таблица «меш → часть (+ экземпляр)» строится один раз при загрузке. Для частей с `select: "each"` экземпляр — прямой потомок узла части, в чьём поддереве лежит меш; для `InstancedMesh` — по `instanceId`.
Подробно с правилами разметки — `docs/05-manifest.md`, «Выбор по клику».
4. Различаем одиночный клик, двойной клик и повторный клик по выбранному; перетаскивание (сдвиг указателя больше порога) кликом не считается.

### Камера
- Подлёт к части: `fitToBox` по габаритам части с учётом `viewportInsets`, чтобы объект был в центре видимой области, а не под панелью или шторкой.
- Сохранение и восстановление позиции и цели в `ViewState`.

### Расслоение
- Исходные позиции узлов частей запоминаются при загрузке манифеста и возвращаются при смене манифеста / `dispose` (модель кэшируется и переиспользуется заглушками).
- Целевые позиции (`explode/explode.ts`), решение 34:
  - **Столбец** (части без `direction`): ось столбца — «вверх» модели (Y), столбец стоит сбоку от габаритов модели (по +X; `explodeLayout.side` в манифесте переопределяет). Части идут сверху вниз по `explode.order` (по умолчанию — порядок в `parts`); высота места = габарит части по оси столбца + зазор; столбец центрирован по высоте относительно модели. Каждая часть получает своё место — совпадение позиций исключено.
  - **Стопка по направлению** (части с `direction`): части с одним направлением выкладываются друг за другом от габаритов неподвижных частей (`stay` и без `explode`) наружу: ближняя грань следующей — за дальней гранью предыдущей плюс зазор. Зазор — доля габарита модели по этой оси, поэтому расстояния равномерные и у вытянутых моделей.
  - `explode.offset` — явное расстояние от исходного положения вдоль направления; `stay` — на месте; `with` — едет с указанной частью.
  - Смещение из координат модели в локальные координаты родителя узла — обратной матрицей линейной части (`Matrix3.setFromMatrix4(rel).invert()`), **не** нормальной матрицей: у родителя с поворотом (`Sketchfab_model` с −90° по X) нормальная матрица разворачивает направление.
- В расслоении (множитель > 0,5) смещённые части с `pick: "pass"` выбираются и подсвечиваются как `select`.
- Камера при включении/выключении — `02-ux-spec.md`, «Расслоение»; `ViewState` хранит `exploded` и `cameraBeforeExplode`, при `restoreViewState` расслоение применяется мгновенно до установки камеры.
- Смещаются только «верхние» корни частей: узел, вложенный в смещаемый корень другой части (рибосомы внутри `RoughER`), пропускается — он едет с предком, без двойного смещения.
- Анимация туда и обратно — сглаживание множителя 0…1 (как `VisualState`), прерванная анимация продолжается из текущей позиции к новой цели. `prefers-reduced-motion` — переходы мгновенные.
- Пикинг, подлёт камеры и сноски работают по смещённым позициям: якорям добавляется текущее смещение части.
- Целевые позиции всегда вычисляются заново из манифеста, а не накапливаются (решение 7).

### Сноски
- Якорь (`labels/label-anchors.ts`): явная точка из манифеста (в координатах модели) или `anchor: "auto"` — точки-кандидаты на поверхности части, вычисленные при загрузке, и выбор видимого кандидата с гистерезисом (`05-manifest.md`, «Якоря сносок»). Центр габаритов не используется: у полых частей он вне части. Части без `label`, с `label.hidden` и без мешей сносок не получают; у `select: "each"` — `label.instance` (по умолчанию первый экземпляр) или `label.each: true` (сноска у каждого).
- Кандидаты (`labels/surface-points.ts`): 8–12 вершин на поверхности части, выборка методом дальнейшей точки, в координатах модели (следуют за расслоением). Покадровый raycast к мешам части не нужен — только проекция точек.
- Выбор кандидата (`labels/project.ts`, `LabelTracker`, каждый отрисованный кадр): видимый (в кадре, не закрыт) кандидат, ближайший к экранному центру части. Смена с гистерезисом: новый должен быть заметно ближе (в `betterFactor` раз) и оставаться лучше ~`hysteresisMs` (300 мс); текущий пропал из кадра/закрыт — смена немедленная; закрыты все — остаётся текущий, сноска приглушается.
- Окклюзия: луч от камеры к точке; ближайший видимый непрозрачный меш (не принадлежащий самой части) закрывает её. «Прозрачность насквозь» — из baseline манифеста (override `material.opacity` / исходный материал), а не из текущего материала, чтобы приглушение изоляции не влияло на перекрытие. Пересчёт с троттлингом (~150 мс, только на отрисованных кадрах); смена состояния — после двух одинаковых проверок подряд (без мигания).

### Визуальные состояния частей

Наведение, выбор, приглушение и изоляция меняются **плавно** (≈150–250 мс), а не мгновенной заменой материала.

- У каждой части (и у каждого экземпляра при `select: "each"`) есть **целевое** и **текущее** визуальное состояние: `highlight` (0…1, наведение), `selected` (0…1), `dim` (0…1, приглушение), `hidden` (изоляция / `include`). Наведение, выбор и изоляция только меняют целевые значения.
- Модуль `highlight/` каждый кадр сближает текущие значения с целевыми (экспоненциальное сглаживание или gsap) и применяет их к материалам. Пока хотя бы один переход не завершён, ядро запрашивает кадры; когда всё устоялось — рендер по требованию снова останавливается.
- **Материалы клонируются один раз при разрешении манифеста — по одному набору на часть (экземпляр)**, а не на каждый кадр и не на каждое наведение. Это обязательно: в модели одни и те же материалы общие для многих мешей (все рибосомы делят один материал), и анимация одной части без клонирования изменила бы и другие. Исходные значения (`emissive`, `opacity`, `transparent`) запоминаются для возврата.
- Применение: `highlight` / `selected` — интерполяция `emissive` и `emissiveIntensity` к цвету акцента; `dim` — `opacity`. Флаг `transparent` переключается только в начале затухания и после полного возврата (переключение меняет шейдерную программу — не делать это каждый кадр); у полупрозрачных частей `depthWrite` выключается на время приглушения.
- Для инстансированных частей (`InstancedMesh`) состояние экземпляра — через `instanceColor` (подсветка) и отдельный экземпляр-«оверлей» для выбранного, т. к. прозрачность по экземплярам штатно не поддерживается.
- `prefers-reduced-motion` → длительность переходов 0.
- Стоимость: несколько десятков частей × изменение пары uniform-значений за кадр — пренебрежимо; шейдеры не перекомпилируются.

### Переход между уровнями
- Ядро держит одну активную сцену и кэш предзагруженных.
- Анимация «старая модель растворяется — новая проявляется» управляется ядром по команде адаптера.
- `dispose` освобождает геометрии, материалы, текстуры.

### Производительность
- Рендер по требованию: кадр рисуется, только когда что-то изменилось (камера, анимация, подсветка).
- `InstancedMesh` для частей с `render.instanced` (рибосомы).
- Модели сжаты meshopt или Draco, текстуры в KTX2.
