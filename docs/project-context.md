# Контекст проекта «Атлас клетки» (сводка на 24.11.2026)

Самодостаточная сводка для чатов и людей без доступа к репозиторию: можно приложить этот файл целиком. Детали — в документах, на которые есть ссылки (пути от корня репозитория, ветка `lab-backend`).

## 1. Что это и зачем

**Продукт.** Обучающая веб-платформа для изучения строения клетки человека на интерактивных 3D-моделях. Студент вращает и приближает модель, выбирает органоиды, читает описание, переходит к детальной модели органоида и обратно, проходит тесты по моделям. В перспективе — атлас органов и систем, загрузка моделей преподавателями.

**Пользователи.** Студенты медицинского университета (в том числе с телефона) и преподаватели (демонстрация на занятиях, в будущем — свои модели и тесты). Проект — сотрудничество аэрокосмического университета (автор) и медицинского университета; медицинскую достоверность текстов проверяет медуниверситет.

**Три контекста проекта:**
1. **Практика / НИР.** Тема практики: «Разработка клиентской подсистемы интерактивной 3D-визуализации на основе веб-технологий». Рабочая тема НИР: «Исследование целесообразности разработки системы 3D-визуализации для обучения студентов медицинских вузов».
2. **Лабораторная по высоконагруженным приложениям** — микросервисный бэкенд (выполнена, раздел 4).
3. **Диплом** — ТЗ пока нет; кандидаты на основной результат — 3D-ядро и система манифестов.

**Ограничения.** Автор один, сроки жёсткие — простые решения. Автор — опытный React-разработчик, Angular осваивает в процессе. Модели — из открытых источников, лицензии разные.

## 2. Клиент

**Стек.** Angular (standalone-компоненты, сигналы, OnPush, zoneless), SCSS, Angular Material + CDK. 3D: three.js, camera-controls, three-mesh-bvh, gsap. Валидация манифестов — zod. Тесты — Vitest.

**Две части:**
- `projects/viewer-core` — **3D-ядро на чистом TypeScript + three.js, без Angular и без знаний о предметной области.** API: `createViewer`, `load(manifest)`, события через `on()`, выбор частей, подсветка и изоляция, расслоение, сноски (`getLabelPositions`, `onFrame`), сохранение/восстановление вида (`getViewState` / `restoreViewState`), кэш моделей в памяти. Подробно — `docs/04-viewer-core.md`.
- `projects/app` — Angular-приложение. Слои: страницы → сторы на сигналах (`AtlasStore`, `QuizRunStore`, …) → репозитории за `InjectionToken` (`STRUCTURE_REPO`, `QUIZ_REPO`, `ANALYTICS_REPO`). Компоненты не делают HTTP-запросы сами. Рендер-цикл three.js не запускает обнаружение изменений Angular. Подробно — `docs/03-frontend-architecture.md`.

**Манифест сцены** (JSON, `docs/05-manifest.md`) — ключевая идея проекта: всё предметное (какие узлы glTF образуют часть, какая сущность за ней, камера, сноски, расслоение, переход к детальной модели) описывается в манифесте, а не в коде. Новая модель подключается без изменения кода. Части выбираются по исходным именам узлов glTF; повторяющиеся органоиды — `select: "each"`; детальные уровни — `detail` (может указывать на заглушку `status: "stub"`).

**Экраны:**
- **Атлас** `/atlas/:root/...` — клетка → детальные модели; выбор, «Подробнее», сноски, «Расслоить», изоляция, крошки, «Назад» с восстановлением вида; справочная панель с описанием и источником модели.
- **Тесты** `/quiz`, `/quiz/:quizId` — модель слева, панель теста справа; вопросы «Что выделено на модели?» (подлёт к части, остальное приглушено), `single` / `multiple`, «Не знаю», обратная связь с карточкой органоида, итог, продолжение после перезагрузки. Спецификация — `docs/lab/quiz-ux.md`.
- **Аналитика** `/analytics` — сводка, самые трудные органоиды, статистика по вопросам, автообновление раз в 10 с.
- Только десктоп; мобильная раскладка заложена в `docs/02-ux-spec.md`, не реализована.

**Модели** (подготовлены скриптами в `tools/`, сжаты meshopt; `docs/07-models-and-licensing.md`):

## 3. Бэкенд (лабораторная) — как работает сейчас

```
Браузер ─▶ API Gateway (C#, YARP, :8080) ─┬─▶ Catalog   (C#, ASP.NET Core, EF Core)   ─▶ catalog_db
             адреса экземпляров из Consul  ├─▶ Quiz      (TypeScript, NestJS, Prisma)  ─▶ quiz_db
                                           ├─▶ Analytics (Python, FastAPI, SQLAlchemy) ─▶ analytics_db
                                           ├─▶ MinIO /models (.glb)
                                           └─▶ web (nginx + сборка Angular)
Quiz ──REST, адрес из Consul──▶ Catalog          (прямая связь: карточка органоида после ответа)
Quiz ──RabbitMQ quiz.events──▶ Analytics         (через брокер: AnswerSubmitted, TestCompleted)
```

- **Gateway** — единая точка входа, один origin (CORS не нужен). Маршруты `/api/catalog|quiz|analytics/**`, `/models/**` → MinIO, `/**` → SPA. Адреса из Consul (опрос сразу при старте и каждые 5 с), RoundRobin, пассивные проверки здоровья, повтор `GET` на другой экземпляр, `503` с JSON без экземпляров.
- **Catalog** — манифесты (целиком в `jsonb` + нормализованные части) и тексты сущностей. Seed из `projects/app/public` под advisory-блокировкой; синхронизация `.glb` в MinIO при каждом старте.
- **Quiz** — тесты, попытки, проверка ответов; анонимный пользователь (`clientId` в `localStorage`, заголовок `X-Client-Id`). Попытка в БД → сервис stateless. Catalog недоступен → `entity: null` (деградация). События публикуются после коммита с publisher confirms.
- **Analytics** — потребитель RabbitMQ (prefetch 10, ручной ack, Pydantic-валидация, невалидное → DLQ, идемпотентность по `eventId`) и API статистики.
- **Инфраструктура:** PostgreSQL 18 (одна инстанция, три БД, у каждого сервиса свой пользователь), RabbitMQ 4.4, Consul 1.22 (регистрация и health checks всех сервисов), MinIO.
- **БД:** `catalog_db` — `entities`, `entity_sources`, `models`, `scene_manifests`, `scene_parts`; `quiz_db` — `quizzes`, `questions`, `answer_options`, `attempts`, `attempt_answers`, `attempt_answer_options`; `analytics_db` — `answer_events`, `test_results`, `question_stats`. ER-диаграммы — `docs/lab/architecture.md`.

**Соответствие ТЗ:** Angular-клиент ✔; 3 микросервиса на C#, TypeScript, Python ✔; прямая связь Quiz → Catalog ✔; брокер Quiz → RabbitMQ → Analytics ✔; PostgreSQL, 14 таблиц ✔; Consul ✔; API Gateway ✔.

**Проверено на стенде:** сквозной smoke-тест; масштабирование (`--scale`); остановка экземпляра под нагрузкой без ошибок; накопление событий в очереди при остановленном Analytics и их обработка после запуска; деградация при остановленном Catalog; DLQ; восстановление после перезапуска любого контейнера за 2–16 с.

## 5. Ключевые решения (полный список — `docs/decisions.md`)

- 3D-ядро отделено от Angular и от предметной области; всё предметное — в манифесте.
- Детальные уровни работают на заглушках; добавление модели не требует кода.
- Модели готовятся скриптами с проверками, исходники в репозиторий не кладутся.
- Позиции частей при расслоении всегда считаются из манифеста; состояние вида сохраняется явно.
- Лабораторная — минимальная версия: без Redis, k6, пользователей; брокер — RabbitMQ; Quiz находит Catalog через Consul; один origin через gateway.
- События — после коммита без outbox; идемпотентность по `eventId` в Analytics.
- Отказоустойчивость gateway: пассивные проверки + повтор идемпотентных запросов; сервисы stateless, состояние — в БД.

## 6. Что не сделано и куда развивать

- **Перед защитой лабораторной:** автору пройти `docs/lab/demo.md`; проверить тексты вопросов (`services/quiz/prisma/seed/quizzes.json`, черновик).
- **Необязательное по лабораторной:** `AtlasContentUpdated` (правка сущности в Catalog → сброс кэша в Quiz), Redis (кэш), k6-замеры, пользователи и роли (JWT на gateway), outbox.
- **Продукт:** мобильная версия, инстансинг рибосом (производительность), редактор манифестов / загрузка моделей, атлас органов и систем, тексты от медуниверситета.
- **Технический долг** — `docs/roadmap.md`, разделы «Исправить…» и «Технический долг».
